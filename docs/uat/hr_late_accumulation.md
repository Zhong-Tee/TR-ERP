# สะสมการมาสาย

## ติดตั้ง

ใช้ migration `supabase/migrations/653_hr_late_accumulation.sql` กับฐานข้อมูลที่ติดตั้ง migration ใบเตือน 432 แล้ว ก่อนนำ frontend รุ่นนี้ขึ้นใช้งาน ไม่ใช้ `db push` รวม migration อื่นที่ยังค้างโดยไม่ตรวจรายการก่อน

วันเริ่มต้นคือ 15 ตุลาคม 2026 ปรับในแท็บสะสมการมาสายได้ก่อนสร้างเคสแรก หลังสร้างเคสจะล็อกวันที่เพื่อรักษาหลักฐานเดิม ไม่ต้องนำใบเตือนเก่าเข้า

## กติกา

- สายหนึ่งครั้งต่อวันทำงาน ใช้เวลาเข้าแรกหรือเวลารับรอง ตารางรายวัน วันหยุด และ WFH ตามระบบเดิม
- ผ่อนผัน 5 นาที วินาทีปัดลงถึงนาที หากเกินผ่อนผันให้นับนาทีจากเวลาเริ่มงาน
- ครบ 3 ครั้งหรือ 120 นาทีเปิดปุ่มสร้างร่างหนึ่งเคส ไม่แบ่งนาทีส่วนเกินไปขั้นถัดไป
- ลาที่อนุมัติแล้วไม่คิดสายในช่วงลา ลาต่อเนื่องจากเวลาเริ่มงานเลื่อนเวลาเริ่มไปสิ้นสุดลา และใช้ผ่อนผัน 5 นาทีจากเวลาใหม่นั้น
- ลาฉุกเฉินที่รออนุมัติและเกี่ยวข้องกับเหตุสาย พักการสร้าง/ดำเนินเคส ลาช่วงบ่ายไม่ยกเว้นสายช่วงเช้า
- ข้อยกเว้นที่ HR บันทึกต้องมีเหตุผลและประวัติผู้พิจารณา การถอนข้อยกเว้นของ HR ไม่ถอนการลาที่อนุมัติแล้ว
- ระหว่างรอแจ้งรับทราบ เหตุใหม่อยู่ในขั้นเดิม ไม่สร้างขั้นถัดไป เมื่อแจ้งรับทราบแล้วเริ่มสะสมเฉพาะเหตุหลังเวลาที่แจ้ง
- ไม่สายครบ 120 วันปฏิทินรีเซ็ตยอดเท่านั้น ไม่ลบประวัติหรือคำเตือนที่ยังมีผล หลักฐานของเคสที่สร้างแล้วไม่หายตามยอด
- ขั้นคือ verbal → written_1 → final → termination_review ขั้นสุดท้ายเป็นเคสเสนอพิจารณา ไม่เลิกจ้างอัตโนมัติ
- คำเตือนทุกขั้นมีอายุหนึ่งปี ใช้วันกระทำผิดแรกสุดในชุดเหตุที่ใช้เตือนเป็นฐานแบบเคร่งครัด จึงไม่มีเหตุใดในชุดถูกใช้นานเกินหนึ่งปี วันที่ครบรอบเป็นวันที่หมดผล (ไม่ใช่วันสุดท้ายที่ยังมีผล)
- ใบก่อนหมดผลไม่ลดขั้นที่ยังมีผลของใบล่าสุด เมื่อใบล่าสุดหมดผลเริ่มขั้นและยอดใหม่ เฉพาะเหตุหลังเวลาหมดผล
- ป้ายหลักรวมคำทักท้วงรอตรวจเดิมกับรายการมาสายที่รอสร้างร่าง ป้ายแท็บสะสมแสดงเฉพาะรายการมาสาย คนละหนึ่งรายการ

## การทบทวนและยกเลิก

สร้างร่าง → เปิดใบเตือน → แก้ไขเพื่อเลือกผู้อนุมัติ → ส่งตรวจ → ส่งอนุมัติ → แจ้งรับทราบ ใช้ Modal ของแอปทุกจุด

แก้เวลา/อนุมัติลา/ยกเว้นเหตุภายหลัง จะคำนวณใหม่และแสดงข้อความทบทวนเคส ระบบตรวจหลักฐานอีกครั้งเมื่อส่งตรวจ ส่งอนุมัติ อนุมัติ และรับทราบ หากข้อมูลเปลี่ยนให้กดทบทวนยอดล่าสุดก่อนอนุมัติและส่งตรวจใหม่ หากยอดไม่ถึงเกณฑ์ หรือขั้นหมดผลเปลี่ยนไป ให้ยกเลิกเคสพร้อมเหตุผล

เคสที่อนุมัติแล้วต้องยกเลิก/เพิกถอนและสร้างใหม่ ไม่แก้หลักฐานเงียบ ๆ เคสที่ปิดแล้วก็เพิกถอนได้พร้อมเหตุผล ประวัติยังอยู่ การยกเลิกเอกสารอย่างเดียวทำให้เหตุที่ยังถึงเกณฑ์กลับมาแสดงในป้ายและปุ่ม ไม่รีเซ็ตยอด

## การคำนวณและสิทธิ์

RPC ฝั่งฐานข้อมูลเป็นแหล่งกติกาเดียวทั้งตารางและป้าย การรีเซ็ตคำนวณจากวันที่ไทยปัจจุบันทุกครั้งที่อ่าน จึงไม่ต้องพึ่ง cron หรือเปิดหน้าเว็บค้างไว้ หน้าและป้ายอัปเดตผ่าน realtime เมื่อมี publication รองรับ และ polling ทุก 60 วินาที/เมื่อกลับเข้าแท็บ

เฉพาะ superadmin, admin, account, hr อ่านและดำเนินการได้ ตารางตั้งค่า/ข้อยกเว้น/audit ไม่มีนโยบายเขียนโดยตรง ฟังก์ชันภายในไม่เปิดให้ authenticated เรียก การสร้างเคสใช้ transaction lock และ unique index ป้องกันเคสซ้ำ

## ทดสอบแยกจากฐานข้อมูลจริง

ติดตั้ง PGlite ชั่วคราว ไม่แก้ dependencies ของแอป:

```powershell
npm install --prefix .tmp/late-accumulation-validation --no-save --package-lock=false @electric-sql/pglite@0.3.14
node scripts/test_hr_late_accumulation.mjs
npm run build -- --outDir .tmp/late-accumulation-validation/build
```

สคริปต์ใช้ PostgreSQL ในหน่วยความจำและ fixture schema ไม่เชื่อม Supabase จริง ครอบคลุมเกณฑ์/ผ่อนผัน/วินาที ข้ามเดือน การลงเวลาซ้ำ การลา/ข้อยกเว้น 120 วัน วันหมดผล ลำดับครบสี่ขั้น การทบทวน ยกเลิก สิทธิ์ และการคงหลักฐานเคสหลังรีเซ็ต
